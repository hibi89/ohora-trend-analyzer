# 개발자용 내부 대시보드 명세 — 10/24~25 MVP

작성: 2026-10-20 KST | 상태: **디자인/계약 명세, 구현 전**
목적: 수집/태깅 파이프라인을 안정적으로 운영·점검하기 위한 **read-only 운영 화면**. 팀원이 만드는 고객사 발표용 프론트엔드와 별개다.

## 1. 필수 UX / 화면

### A. 상태 요약
- 마지막 P6 RAW export/snapshot 시각 및 freshness (read-only 사실만)
- 태깅 작업 대기/진행/성공/재시도대기/실패/검수필요 건수
- 마지막 정상 분석 실행 시각, model_id/prompt/taxonomy_version
- 데이터 분류: synthetic sample / 승인된 실샘플 / 운영, 분명히 구분

### B. 게시물·미디어 상세 (사용자 제안 '포켓몬 카드' + 큰 이미지 양쪽)
```text
┌──────────────────────────┬──────────────────────────────────┐
│   큰 이미지 / 캐러셀    │   태그 카드 (7축 P0 표시)        │
│   자식 이미지 순서      │   주색·시어/시럽·캣아이·기법…     │
│   원본 게시물 열기      │   unknown / not_evaluated 배지   │
│                          │   판정 근거 / AI 버전 / 검수 상태│
├──────────────────────────┴──────────────────────────────────┤
│ 국가(공식 roster), 계정, 작성 시각, 관측 시각, 좋아요·댓글 │
│ 값 NULL/0 정확히 구분, 원본 출처, 실행 ID, 재분석 이력      │
└─────────────────────────────────────────────────────────────┘
```
- 이미지 클릭→상세 모달 또는 새 상세 페이지. PC에서는 좌측 이미지 + 우측 태그, 모바일은 세로.
- 캐러셀은 게시물 단위 묶음, **각 이미지 분석 결과는 자식 media별**.
- VIDEO/REELS: 썸네일/원문 링크·`unsupported_video` 상태. 영상 프레임 분류 성공처럼 표시 금지.

### C. 오류/복구 현황
- 최근 오류 목록: `job_id, stage, reason, attempts, retry_after, last_seen`.
- 오류 코드/원인 구분: 이미지 URL 만료, 외부 API 429, JSON invalid, DB 오류, source export 누락.
- '재시도' 버튼은 **이번 MVP에서는 표시하지 않음**. 운영 재실행은 명시된 별도 n8n 제어 경로/권한 검수 후 추가.

### D. 필터/검색
- 국가: KR/US/JP (roster 근거)
- 게시 날짜 vs 관측 날짜를 혼동하지 않는 기간 필터
- P0 태그 7축 필터, 미분석·검수필요 상태 필터
- 정렬: 최근 수집/최근 분석/좋아요 등 숫자 NULL 정렬 정의

## 2. 데이터 연결 원칙

- 화면 → read-only DERIVED DB view 또는 API. 기존 P6 운영 DB 직접 SELECT조차 환경 승인 전 금지.
- 좋아요·댓글/계정 정보는 source snapshot에서 최신 관측값을 표시하되, 값의 observation time 같이 노출.
- 화면 새로고침, 필터링, 캐러셀 이동으로 **n8n 실행·LLM 요청·Meta API 호출 0회**.
- UI에서 태그를 임의 수정해 AI 원출력 덮어쓰지 않는다. 이후 담당자 검수는 별도 review_event append-only.
- LLM 결과를 저장하지 못한 경우 '대시보드 빈 화면'으로 숨기지 말고 실패/미분석 상태 표시.

## 3. 화면 구현 우선순위

**필수:** 현황 4~6개 카드, 최근 작업 목록, 1개 이미지 상세 화면, 태그/정보/근거, 오류 목록.
**선택:** 차트·랭킹·다국어 UI·오호라 SKU 연결·권한형 수정·트렌드 수명 분석.

Streamlit이 기본 후보이나 실제 팀 프론트엔드와 무리하게 프레임워크를 맞추지 않는다. 기술 선택보다 읽기 전용 계약을 먼저 고정.

## 4. 완료 기준

- [ ] 실샘플 또는 synthetic 화면의 출처를 화면에 명시
- [ ] media 1건 + P0 7축 + 태그 근거 + 작성/관측 일시를 상세 보기로 확인
- [ ] 전체 tag dictionary 14축은 조회할 수 있으나 미실행 7축을 분석 완료로 오인하지 않음
- [ ] F5 3회, 필터 3회 사용 시 모델 API/n8n 실행 0회
- [ ] NULL vs 0 표시 구분 (예: '미수집' vs 숫자 0)
- [ ] 부분 캐러셀과 VIDEO 상태를 정확히 구분
- [ ] 읽기 전용 DB 권한 테스트: INSERT/UPDATE/DELETE 차단
- [ ] 실제 운영 DB/RAW의 파일 체크섬 변경 없음

## 5. 팀 발표 화면과 관계

팀원 프론트엔드에는 `POST + MEDIA + DERIVED_TAGS + METRICS + PROVENANCE`의 조회용 응답만 전달한다. 내부 관리 UI가 완성되어야만 팀 발표 UI가 시작할 수 있는 구조로 만들지 않는다. 양쪽이 동일 read-only 계약을 사용하도록 한다.
