# 태깅 품질 수동 검수 프로토콜 v1.1 — 실제 이미지 준비 전

작성: 2026-10-20 | 상태: **검수 기준 설계**, 사람 라벨·AI 정확도 수치 없음.

## 목적

태그 수가 159개라 해도 **실제로 맞게 분류하는지** 검증하지 않으면 '현업 가능'을 주장할 수 없다. 이번 KDT MVP는 **P0 일곱 축(84개 세부 태그)**만 먼저 평가한다. 오호라 내부 정식 코드 체계가 아니라 팀에서 제안한 분석 분류안이다.

## 1. 검수 대상 표본

- 우선 **권한 확인된 이미지 30~50장**을 사용해 1차 정성 점검. 임의 SNS 원본 DB/이미지를 공개 GitHub에 저장하지 않는다.
- 국가 KR/US/JP는 P6 공식 계정 roster에 근거한 계정 그룹을 사용할 수 있을 때만 구분. 캡션 언어로 국가를 추정하지 않는다.
- 한 종류(프렌치·시럽 등)만 뽑지 말고 다양한 색·기법·패턴·입체 장식, 부분 손톱 노출, 반사광, 저해상도, 캐러셀 자식까지 포함.
- 오류 경계 사례: 시럽/시어/젤리, 마그넷/쉬머, 크롬/미러(미러 F04는 이번 미평가), 그라데이션/옴브레, 평면 리본/3D 리본, 글리터/쉬머.
- 실데이터가 부족하면 먼저 **합성 예시로 출력 스키마**만 검증하고 실사진 정확도를 추정하지 않는다.

## 3. 추천 판단 순서

1. 먼저 원본 이미지를 사람 눈으로 보고 `visible_scope`와 `is_nail_design` 판정. 접근불가/비네일은 작업 단위로 분리.
2. 검수자는 분류 기준서와 태그 사전만 읽고 **모델 결과를 보기 전** 참값(gold label)을 만든다(기대치 편향 감소).
3. 가능하면 두 명이 독립 검수한 뒤 의견이 다른 태그는 합의·불일치 사유를 기록한다. 한 명만 가능하면 `single_review`로 표시.
4. 모델 결과를 나란히 놓고 정확히 **tag_id 다중 레이블 집합**을 비교한다.
5. `unknown`(봤으나 식별 실패), `not_applicable`(충분히 보이는 범위에서 해당 없음), `not_evaluated`(검사 안 함)를 혼동하지 않았는지 검토.
6. 모호 태그는 억지로 한 개를 정답 처리하지 말고 판정 보류·근거 부족 사유를 남긴다.
7. 문제 사례를 보고 태그 ID 의미를 몰래 수정하지 않는다. 판정 규칙/프롬프트를 고치면 새 `prompt_version`, taxonomy 기준 변경이면 새 taxonomy 버전으로 분리.

## 4. 지표와 계산 규칙

- **형식 유효율:** 올바른 JSON 및 허용 tag_id를 내는 분석 건수 / 분석 시도 건수.
- **축별 실제 태그 Precision:** TP/(TP+FP). 빈 분모는 N/A.
- **축별 실제 태그 Recall:** TP/(TP+FN). 빈 분모는 N/A.
- **축별 F1:** Precision·Recall이 유효할 때 2PR/(P+R).
- **태그 정확 일치율:** 예측 태그 ID의 집합과 사람 태그 ID의 집합이 완전히 같은 미디어/축의 비율.
- **Abstention(판정 보류)율:** 평가 대상에서 AI가 `unknown`으로 기록한 비율. 낮은 unknown이 반드시 좋은 모델을 의미하지는 않음.
- **상태 정확성:** observed/unknown/not_applicable의 혼동 행렬; P1 `not_evaluated` 허위 분석 건수는 별도 제로 목표.
- **근거 검증율:** 이미지에 실제로 뒷받침되는 모델 근거 비율. 사람이 볼 수 없는 시술 재료·상품명 추정은 오류로 기록.

**정해진 30~50장은 소규모 편의 표본**이므로 국가별/태그별 통계적 대표성 주장 금지. 표본에 포함되지 않은 태그는 단순히 `미평가`라고 명시한다.

## 5. MVP 품질 승인 게이트

- 반드시 충족: 미등록 태그 ID의 **DERIVED DB 성공 저장 0건**, 비네일/입력불가에 대한 가짜 태깅 성공 저장 0건, P1 미평가 축의 허위 태그 0건.
- 반드시 충족: 태그 정본 `1.1.0` 기록, 게시물/미디어/분석 원본과 결과 버전 구분, 프론트엔드 조회/F5에서 모델 자동 재호출 0회.
- 실제 모델 **정확도 숫자 목표**는 현장 기준·평가 데이터가 없어 임의로 정하지 않는다. 우선 혼동 사례를 수집해 사용 목적에 맞는 허용치를 팀이 승인한다.
- 검수 결과가 나쁘면 "태그 사전 159개 완성"과 "AI 태깅 현업용 정확도 확보"를 분명히 구별해 보고한다.

## 6. 내일 담당자에게 넘길 사항

- 검수 샘플 소유자·사용 권한, 모델 API/비용, 기록 저장 위치(공개 GitHub **금지**).
- P0 7축 출력과 정규화 스키마 분리, `unknown`/NA 상태 처리 확인.
- 검수 실패 사례는 개인정보·실계정 URL 제거 후 익명 형태로 코드 테스트 fixture로 재구성 가능.
