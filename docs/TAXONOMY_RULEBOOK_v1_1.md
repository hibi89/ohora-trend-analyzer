# OHORA Trend Analyzer — 태깅표 v1.1 설계 기준서

**작성:** 2026-10-20 KST  
**범위:** 팀 프로젝트용 제안 기준. 오호라의 비공개 공식 내부 분류표 또는 네일업계 단일 국제 표준이 아니다.

## 1. 왜 만드는가

Meta API에서 수집한 원본 게시물·미디어·시점별 반응 데이터를 장기간 보존해 AI 분류 기준이나 모델이 달라져도 RAW 재수집 없이 재분석할 수 있게 한다. 상품기획 담당자는 사진과 함께 색·기법·패턴·장식을 조회할 수 있고, 개발자는 버전 있는 태깅 사전과 감사 이력을 이용해 개선한다.

## 2. 이번 릴리스

- **14개 대분류, 159개 불변 tag_id 유지** (변경·삭제 0).
- P0 7축은 **F01 색상(18), F03 발색·투명도(8), F05 효과·재질감(12), F06 기본 기법(10), F08 패턴(12), F09 모티프(14), F10 입체 장식(10)**. 총 **84개**.
- P1 7축은 F02·F04·F07·F11·F12·F13·F14. P0 실행 결과에서 반드시 `not_evaluated`.
- S01(주색·보조색·포인트색), S02(베이스·기법·장식 관계), S03(손톱별 구성), S04(대표·부가 요소)는 향후 디자인 ID용 구조 정보로 유지. S01/S04도 이번 제출에서 미구현이면 `not_evaluated` 또는 분석 미실행 상태를 명시.
- 84개 P0 세부 태그에 대한 시각 판정 기준은 JSON 규칙 파일에 수록. 모델 프롬프트와 사람 검수에서 함께 이용.

## 3. 핵심 상태 구분

| 상태 | 의미 | tag_ids |
|---|---|---|
| `observed` | 실제 분석하고 명확하게 판정 | 1개 이상 |
| `unknown` | 분석했지만 사진 근거 부족 | 빈 배열 |
| `not_applicable` | 분석했고 충분히 보이는 범위에서 해당 속성 없음 | 빈 배열 |
| `not_evaluated` | 이번 실행에서 해당 축을 분석하지 않음 | 빈 배열 |

영상 분석 미지원이나 이미지 접근 불가는 **작업 상태**(예: `unsupported_video`, `input_unavailable`)로 처리. 이미지가 없을 때 가짜 태그 상태를 만들지 않는다. v1.0 `not_observed`는 여러 뜻이 섞여 있어 자동 변환하지 않는다.

## 4. 판정 규칙 핵심

| 쟁점 | 권장 판정 |
|---|---|
| 시어·시럽·젤리 | 각각 독립적인 시각 발색. 투명하다고 무조건 시럽/젤리로 태깅하지 않음 |
| 그라데이션·옴브레 | 그라데이션은 상위 개념, 옴브레는 둘 이상의 색/톤 전환. 서로 공존 가능 |
| 크롬·미러 | 크롬 F05 효과, 미러 F04 마감. F04는 이번 P0에서 미실행 |
| 캣아이·쉬머 | 집중 광선/빛띠 근거 필요. 일반 쉬머만으로 캣아이 금지 |
| 꽃·리본 2D/3D | 모티프 F09, 돌출 장식 F10. 높이가 실제 확인될 때 F10 추가 |
| 색상·재질 | 골드/실버는 색상, 메탈릭/크롬은 효과. 시술 재료를 사진으로 단정 금지 |
| 디자인 전체 vs 일부 | 잘린 사진·캐러셀 일부만 있을 때 전체 손톱이 같다고 추정하지 않음 |

## 5. 데이터 보존·ID·재분석

- P6 RAW는 읽기만. **AI 태깅 결과는 반드시 다른 DERIVED DB**에 저장.
- 단위: Instagram post 1개 ≠ image media 1개 ≠ 디자인 클러스터 1개. 캐러셀 각 이미지 별로 분석 후 게시물 수준에서 집계.
- 결과에 `post_id`, `media_id`, `source_observation_ref`, `taxonomy_version`, `model_id`, `prompt_version`, `analyzed_at`, `analysis_input_hash`, `facet_results`, `evidence_source`, `review_status` 보존.
- 신뢰도 수치는 모델이 자체 제시한 수치로, 평가된 정확도 확률이 아님.
- 조회/F5는 저장된 데이터만 읽고 외부 AI 재호출 금지. 이미지·캡션·모델·프롬프트·태그 버전이 바뀌면 재분석하고 기존 결과 보존.

## 6. 오호라 공개몰 대응과 한계

오호라 공개 쇼핑 필터(Magnet, Chrome, French, Jelly, Solid, Gel Strips 등)는 제안 태깅표와 연결 가능하지만 외부 인스타그램 네일 사진만으로 **오호라 제품 사용, SKU, 젤스트립/프레스온 제품 타입**을 임의 판단하지 않는다. 회사 내부 분류표 확인 전에는 공식 내부 표준으로 발표하지 않는다.

## 7. 검증 기준

- 14개 축 / 159개 원래 태그 ID 정확히 유지, 중복 0.
- P0 7축 / 84개 태그 판정 기준, P1 7축은 미분석 상태.
- 결과 태그 ID가 사전에 존재하며 해당 축 prefix와 일치.
- 응답 상태값/태그 배열 관계 검증, 이미지 없음/비네일은 별도 작업 상태.
- 촬영·조명 편향을 고려하고, F02 색상 특성·F13 무드·F14 시즌/맥락은 섣부른 추정을 자제.
- 실제 이미지 정확도 검증은 **미수행**. 권한 있는 이미지 30~50장 검수 이후에만 품질 수치를 말할 수 있다.

## 8. 파일과 GitHub 상태

- GitHub 등록 확인: `hibi89/ohora-trend-analyzer`의 `taxonomy/tag_schema_v1_1.json` — v1.1 14축 159태그 구조/상태 규칙.
- 정본은 GitHub의 `taxonomy/tag_schema_v1_1.json` 및 `taxonomy/tag_rules_v1_1.json`으로 유지한다. XLSX는 팀원 검토용 편의 파일이며, AI 판정 규칙은 코드에서 명시적으로 불러와야 적용된다.
- 내일은 n8n 구현. 오늘은 태깅 사전 규격과 사람 검수·기계 검증까지로 한정한다.
## 9. 변경 관리

- `1.1.0`은 **팀 프로젝트 데이터 사전 기준 버전**이다. 실제 AI의 판정 정확도 및 오호라 내부 승인 여부와 구분한다.
- 오늘 이후 태그 ID 재정의·삭제 금지. 추가/규칙 변경 시 별도 버전을 발행하고 `taxonomy_version`, `model_id`, `prompt_version`과 결과 실행 이력을 남긴다.
- `not_evaluated`는 검사하지 않은 축이다. 빈 태그 배열만으로 디자인 요소의 부재를 단정하지 않는다.
- 판정 규칙서와 JSON이 충돌하면 담당자 검토 후 동일 버전으로 동기화하고 테스트를 재실행한다.

## v1.1 검증·저장 직전 요구사항 (2026-10-20 추가)

- [P0 정규화 결과 JSON Schema](../taxonomy/p0_tag_result.schema.json) 사용. 모든 14축을 정확히 한 번씩 포함하되 P0 7개만 실제 평가, P1 7개는 반드시 `not_evaluated`.
- `not_applicable`에는 실제 검사한 눈에 보이는 범위에서 부재를 판단한 근거를 `evidence_note`에 기록한다. 부분 이미지에서 다른 손톱의 부재를 단정하지 않는다.
- 잘못된 `facet_id`, `status` 자료형은 예외로 프로그램을 중단시키지 않고 검증 오류로 처리한다.
- 정규화 결과는 모델 원본 출력과 구분한다. LLM provider Structured Output에 이 전체 JSON Schema를 그대로 넣으면 호환성 문제가 발생할 수 있으므로 모델 출력은 별도 소형 계약으로 받는다.
- 로컬 합성 계약 테스트 36건 PASS(원본 GitHub Actions 실행 결과는 별도 확인 필요). 상세 인계: [TAGGING_INTEGRATION_HANDOFF_v1_1.md](TAGGING_INTEGRATION_HANDOFF_v1_1.md).
